# 高效执行管线（通用核心）

## 目标

用最短路径完成「定位 → 实现 → 自检 → 交付」，减少无效全仓扫描与重复试探；可复用知识写回正确层级，形成沉淀闭环。**交付 = 输出结果（改动文件 + 回复），不等于 git 提交**；提交动作仅由用户指令触发。

## 触发场景

- 任务开始：不确定执行顺序、该读哪些文件
- 不知道改动落点、涉及哪些模块
- 跨模块 / 跨应用链路改动
- 仅改文档 / 规范 / 协作文件
- 需要沉淀可复用经验（知识写回）
- 任务收尾：交付结果后**不主动提交**；用户明确要求提交时才进入 `commit` 流程

## 默认读取顺序（全工具）

1. 下游仓库根 `AGENTS.md`（L0 真源）
2. 按意图加载对应 skill（`workflow` / `code-dev` / `self-check` / `commit` / 本地 `business-map`）
3. 目标应用 / 包 `README` + 同模块 3～5 个现有文件（对齐风格）
4. 若存在根 `TODO.md`：任务结束按 `self-check` 维护
5. （可选）工具专属薄入口（`.codex/` / `.workbuddy/` / `.cursor/rules` 等）

冲突优先级：`AGENTS.md` > `.agents/project/*` > 通用 skill 正文 > 工具薄入口。

## 工具习惯（通用）

| 动作 | 优先 |
|------|------|
| 搜符号 / 中文 / 路径 | 全文搜索 / 文件名匹配类工具 |
| 读文件 | 精确读取（大文件分段） |
| 改已有文件 | 精确替换 |
| 新建文件 | 仅必要时 |
| 跑命令 | shell（lint / build / git 状态） |

- 互不依赖的探查 **并行** 做
- 禁止用脚本批量改一堆无关文件
- 工作区已有大量 uncommitted 改动时：**不碰无关 diff**

## 场景策略

### A. 单点小改（≤3 文件）

读目标文件 + 1 个同类参考 → 改 → 局部 lint → 结束。

### B. 单模块 / 单应用功能

读模块 README + 同域 feature 全链路 → 实现 → lint 改动路径 → 受影响模块 build。

### C. 跨模块 / 跨包链路（最常见踩坑）

1. 先画链路：接口 / 字段 / 枚举流经哪些包与应用
2. **先定契约**（路径、字段、枚举值）再写代码
3. 改序建议：低层（类型 / 数据）→ 高层（调用方 / UI）
4. 每端各自局部 lint；收口时再按需 build 全部受影响模块

### D. 仅规范 / 文档 / 协作文件

改 `AGENTS.md`、`.agents/**`、编辑器 rules 等：`git diff --check` 即可，**不**跑应用 build（除非下游 `AGENTS.md` 另有要求）。

### E. 调查类（学习代码 / 回答问题）

只读 + 总结；不写文件除非用户要产出文档；可写工具侧记忆笔记。

## 规则治理与知识沉淀

### 分层模型（下游仓库参考结构）

| 层 | 位置 | 写什么 |
|------|------|--------|
| **L0** | 根 `AGENTS.md` | 本仓边界、编码纪律、栈摘要、Git |
| **L1a** | 通用 skills（`@142vip/agent-skills` 真源 → `.agents/skills/` 镜像） | 跨项目流程：`workflow` / `code-dev` / `self-check` / `commit` |
| **L1b** | `.agents/skills/business-map`（仅本仓） | 本仓业务落点 |
| **L1c** | `.agents/project/*` | 本仓 build 映射、栈摘要 |
| **L2** | 工具薄入口（`.codex/` / `.workbuddy/README.md` / `CLAUDE.md` 等） | **仅**工具操作差异 |
| **L3** | 编辑器 rules（`.cursor/rules` 等） | 编辑器触发层（内参，不对外） |

### 知识写回表

| 发现 | 写回目标 |
|------|----------|
| 跨项目通用编码 / 自检 / Git 提交流程 | **必须**写回 `@142vip/agent-skills` 真源 `skills/<name>/SKILL.md` → 发版 → 下游 upgrade；**禁止**只改下游镜像 || 本仓编码纪律 / 边界 | 根 `AGENTS.md` |
| 本仓业务落点 / 近期模式 | `.agents/skills/business-map` |
| 本仓构建命令映射 | `.agents/project/build-map.md` |
| 某工具命令习惯 | L2 工具薄入口 |
| 人类也要看的命令 / 架构 | 根 README / `docs/` |
| 待办 | 根 `TODO.md`（存在才写） |

### 铁律

- **单一真源**：通用流程只维护在 `@142vip/agent-skills` 包内 `skills/<name>/SKILL.md`
- **下游禁止手改镜像**：`vip-agent-skills` / `fa ai sync` 已覆盖的 `workflow` / `code-dev` / `self-check` / `commit` **不得**在下游仓本地改完就提交；改进必须回写真源 skill → 发版 → 下游 upgrade + sync
- **禁止只改镜像不改包**（真源仓内误改镜像 → 同一任务回写包内文件）
- `business-map` 等业务落点 skill **永不**进 npm 包、永不被同步工具覆盖
- 工具薄入口**禁止**复制编码纪律全文（只补「怎么搜 / 怎么改 / 怎么批」差异）
- 会话 memory 不进仓库；稳定知识只写 L0 / L1
- 对外交付与业务文档**不引用**内部 rules 路径
- Commit message **禁止** Agent / IDE / 大模型 trailer（见 `commit` skill）

## 回复模板（强制精简）

### 日常

```markdown
## 结论
（1～2 句）

## 验证
- <lint 命令> → 结果
- （如有）<build 命令> → 结果

## 变更
- `path`：说明
```

> **提交**：默认不执行 git 提交——任务完成即交付结果；用户明确要求提交时才按 `commit` skill 执行（**push 由用户手动操作，agent 不执行**）。

### 纯问答

直接答；可附关键路径；不套验证模板。

## 明确禁止

| 禁止 | 原因 |
|------|------|
| 未定位就全仓扫描 | 先搜再精读 |
| 默认全仓 lint / build | 拖慢回复（见 `self-check`） |
| 碰工作区无关的 uncommitted 改动 | 越权 |
| 脚本批量改无关文件 | 最小改动原则 |
| 对外暴露内部 rules 路径 | 内参不外露 |
| 未执行却写「应该会通过」 | 诚实铁律 |
| 未获用户明确要求就 `git commit`；执行 `git push` | 越权；提交权在用户，交付 ≠ 提交；**push 由用户手动操作** |
